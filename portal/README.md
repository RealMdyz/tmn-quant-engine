# سه‌سبد (TMN Portal): پلتفرم چندکاربره روی موتور TMN Quant Engine

کاربر ثبت‌نام می‌کند، به پرسشنامه‌ی ریسک جواب می‌دهد، تخصیص سرمایه‌اش بین سه استراتژی موتور (کم‌ریسک: بازارساز، متوسط: سبد ریال، پرریسک: سبد بتا) مشخص می‌شود، اشتراک می‌خرد و ربات را روشن می‌کند. حساب بنیان‌گذار (`FOUNDER_EMAIL`) به ربات اصلی روی لیارا و حساب واقعی والکس وصل است و «اتاق کنترل» را می‌بیند.

> این پوشه به ربات دست نمی‌زند: کد `bot/` و تنظیمات آن تغییری نکرده‌اند و پلتفرم فقط می‌خواند (صفحه‌ی وضعیت ربات، شاخه‌ی `runtime-logs` و موجودی حساب والکس).

## معماری

```
                    ┌────────────── سه‌سبد (یک برنامه‌ی جدید در لیارا) ──────────────┐
 مرورگر کاربر ────► │ FastAPI  /api/*  +  رابط فارسی (portal/web، بدون build)        │
                    │   ├─ ثبت‌نام/ورود (scrypt، نشست سمت سرور)                      │
                    │   ├─ پرسشنامه ← امتیاز ← تخصیص (risk.py)                       │
                    │   ├─ اشتراک و پرداخت (demo / زرین‌پال)                          │
                    │   └─ SQLite روی دیسک لیارا (یا PostgreSQL با DATABASE_URL)     │
                    │ worker (نخ پس‌زمینه)                                           │
                    │   ├─ هر ۶۰ ثانیه: ۱ درخواست قیمت والکس ← یک قدم برای همه‌ی ربات‌ها │
                    │   └─ هر ۲۰ ثانیه: حساب واقعی والکس + وضعیت ربات اصلی            │
                    └──────────┬──────────────────────────────┬──────────────────────┘
                               │ فقط خواندن                    │ فقط خواندن
               ربات اصلی روی لیارا (BOT_STATUS_URL)      API والکس (WALLEX_API_KEY)
               + شاخه‌ی runtime-logs (GITHUB_TOKEN)
```

هزینه‌ی بازار با تعداد کاربر زیاد نمی‌شود: یک بار قیمت گرفته می‌شود و همه‌ی ربات‌ها با همان قیمت یک قدم جلو می‌روند.

## پرسشنامه و امتیاز ریسک (`app/risk.py`)
۱۰ سؤال، هر جواب ۰ تا ۴ امتیاز، در دو بُعد:
- **ظرفیت ریسک** (توان مالی): افق سرمایه‌گذاری، سهم از پس‌انداز، پایداری درآمد، پس‌انداز اضطراری، سن
- **تمایل به ریسک** (نگاه به ضرر): تجربه، واکنش به افت ۱۵٪، حداکثر افت قابل تحمل، انتخاب سناریو، هدف

`امتیاز = min(میانگین دو بُعد، بُعد کمتر + ۱۰)`. یعنی کسی که ضرر را دوست دارد ولی توانش را ندارد، پرریسک حساب نمی‌شود.

| امتیاز | پروفایل | کم‌ریسک / متوسط / پرریسک |
|---|---|---|
| ۰ | محافظه‌کار | ۸۵ / ۱۵ / ۰ |
| ۲۵ | محتاط | ۶۰ / ۳۰ / ۱۰ |
| ۵۰ | متعادل | ۳۵ / ۴۰ / ۲۵ |
| ۷۰ | رشدگرا | **۲۰ / ۳۵ / ۴۵** (همان تخصیص فعلی ربات اصلی در `config.yaml`) |
| ۱۰۰ | جسور | ۵ / ۲۵ / ۷۰ |

بین این نقطه‌ها خطی درون‌یابی می‌شود. کاربر می‌تواند تخصیص را **محافظه‌کارانه‌تر** کند، ولی پرریسک‌تر از پیشنهاد نه.

## ربات کاربران (`app/simulator.py`)
در این نسخه ربات هر کاربر در **حالت آزمایشی** است: پول مجازی، قیمت‌های لحظه‌ای والکس، و همان قوانین `config.yaml`:
- سبد ریال (BTC/ETH) و سبد بتا (PEPE/ADA/LINK) فقط وقتی وارد می‌شوند که تتر/تومان در ۴۸ ساعت حداقل ۱٪ رشد کرده باشد.
- حد ضرر فاجعه: ۵٪ سبد ریال، ۷٪ سبد بتا.
- خرید به بهترین قیمت فروش و فروش به بهترین قیمت خرید، هر دو با کارمزد Taker (محافظه‌کارانه).
- سهم کم‌ریسک (بازارساز) در حالت آزمایشی تومان نقد می‌ماند: بازارسازی را نمی‌شود با قیمت بالای دفتر صادقانه شبیه‌سازی کرد، و بک‌تستش هم نزدیک صفر بوده است. این در رابط کاربری هم نوشته شده است.

## اتاق کنترل بنیان‌گذار (`app/telemetry.py`)
- **حساب واقعی والکس:** ارزش همه‌ی دارایی‌ها به بهترین قیمت خرید (مثل خود ربات)، سود و زیان نسبت به ۵ میلیون تومان اولیه، تفکیک دارایی‌ها به سبدها، سفارش‌های باز و نمودار دقیقه‌ای.
- **الگوریتم روی لیارا:** حالت (shadow/live)، تازگی داده، ارزش، افت، آمار بازارساز، وضعیت سبدها، رژیم تتر، آخرین تصمیم AI با استدلالش، رویدادها با فیلتر و خروجی خام کنسول.
- **پلتفرم:** کاربران، اشتراک‌ها، درآمد، ربات‌های فعال، توزیع پروفایل‌ها و جدول کاربران.

منابع داده‌ی ربات (هر کدام که تنظیم شده باشد):
| متغیر | چه می‌دهد | تأخیر |
|---|---|---|
| `BOT_STATUS_URL` | صفحه‌ی وضعیت فعلی ربات در لیارا (`/`، `/decisions`، `/bot`) | لحظه‌ای |
| `GITHUB_TOKEN` | تاریخچه‌ی کامل ارزش، سبدها و تصمیم‌ها از شاخه‌ی `runtime-logs` | ~۱۰ دقیقه |
| `BOT_LOGS_DIR` | پوشه‌ی `logs/` ربات، وقتی هر دو روی یک سرور باشند | لحظه‌ای |

## اجرای محلی
```bash
pip install -r portal/requirements.txt
MARKET_SOURCE=replay SEED_DEMO=1 FOUNDER_EMAIL=me@example.com FOUNDER_PASSWORD=Pass12345 \
  uvicorn portal.app.main:app --port 8000          # از ریشه‌ی مخزن
python -m portal.tests.test_portal                  # تست‌های آفلاین
```
`MARKET_SOURCE=replay` قیمت‌ها را از `data/hourly.json` بازپخش می‌کند (وقتی والکس در دسترس نیست). روی سرور `wallex` بگذارید.

## استقرار روی لیارا
1. یک برنامه‌ی **Docker** جدید بسازید (مثلاً `tmn-portal`) و یک دیسک به نام `portaldata` برایش بسازید.
2. متغیرهای `portal/.env.example` را در تنظیمات برنامه وارد کنید (حداقل `PORTAL_SECRET`، `PUBLIC_URL`، `FOUNDER_EMAIL`، `FOUNDER_PASSWORD`، `BOT_STATUS_URL`، `WALLEX_API_KEY`).
3. از ریشه‌ی مخزن:
   ```bash
   liara deploy --app tmn-portal --liara-json portal/liara.json --dockerfile portal/Dockerfile
   ```
4. با `FOUNDER_EMAIL` وارد شوید؛ مستقیم به اتاق کنترل می‌روید.

## امنیت
رمزها با scrypt، نشست‌ها با توکن تصادفی (فقط هش آن ذخیره می‌شود) در کوکی HttpOnly/SameSite، هدر ضد CSRF برای همه‌ی درخواست‌های تغییردهنده، محدودیت تلاش ورود، CSP سخت‌گیرانه (فونت هم روی خود سرور است). کلید والکس فقط در متغیر محیطی است و فقط برای خواندن استفاده می‌شود.

## فاز بعد
- **معامله‌ی واقعی برای کاربران:** هر کاربر کلید API والکس خودش را (فقط با دسترسی معامله، بدون برداشت) وصل می‌کند و یک «اجراکننده» سفارش‌های سبدها را به نسبت تخصیص او روی حساب خودش می‌گذارد. شرط لازم: موتور از قالب مسابقه (`end_time`، فروش پایانی) جدا شود و این مسیر روی حساب‌های کوچک تست شود.
- درگاه زرین‌پال با `ZARINPAL_MERCHANT_ID` (کد آماده است ولی با درگاه واقعی تست نشده)، PostgreSQL و worker جدا برای تعداد کاربر زیاد.
